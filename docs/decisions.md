# Decisions and tradeoffs

Why Overhear works the way it does, and what each choice costs. One rule sits under almost all of them: when the call record can't prove something, Overhear says so. A missed problem costs some value. A false alarm costs trust, and a checker nobody trusts is worthless. So most choices here give up recall to protect precision.

## The verdict

- **Code decides every verdict. No AI model does.** Overhear reads the agent's words with rules, and checks them against the tool calls in the record.
  - The cost: a promise phrased in a way the rules don't know goes unnoticed.
  - A model may one day suggest claims for a person to confirm, but it will never mark a call Failed on its own.
- **"Couldn't check" over guessing.** When the record can't decide a rule, that rule reads Couldn't check and the call reads Needs review. It never reads Passed. The cost: more calls for a person to look at.
- **How the call sounded never changes the verdict.** Goodbye loops, system errors read aloud and robotic dates get their own "Call experience" line. The cost: a call that kept every promise but felt bad still reads Passed. The line is how you find out.
- **Nothing done is narrow.** It needs a caller who said 10 words or fewer, no tool call and no promise. The cost: a short question the agent handled well can read Nothing done.
- **A caller who hangs up during a transfer announcement isn't a failed transfer.**
  - If the caller hangs up within 8 seconds of the agent finishing (speech is estimated at 2.5 words a second), the transfer check reads Couldn't check.
  - A caller who keeps saying "Hello?" past that point, or waits in silence, is still Failed.
  - The cost: both numbers are estimates, so a slow talker or a long pause can tip a call either way. A record without word timestamps always reads Couldn't check.
- **A booking claimed before any attempt stays Failed, even if the caller hangs up.** The caller left believing something false.
- **An unknown transfer tool means Couldn't check.** If Overhear doesn't know an agent's transfer tool, a transfer claim with no transfer reads Couldn't check, because Overhear can't tell "never attempted" from "attempted through a tool it didn't recognise". Giving Overhear a policy file that names every tool the agent has turns on the strict check: with a policy and no transfer tool in it, that claim reads Failed (`docs/policy.md`).

## Platforms

- **Retell, then LiveKit Agents.** Vapi and ElevenLabs come later.
- **LiveKit calls come in as files.** A LiveKit agent saves one session report per call (`ctx.make_session_report().to_dict()`), and Overhear reads those files. The cost: a few lines of code in the agent first.
- **Tool success is never taken from the platform alone.** Retell's `successful` and LiveKit's `is_error` only say whether the tool raised. So the order is: the platform saying the tool failed means failed. Otherwise the success field the agent's policy names decides, when the payload has it. Otherwise the platform saying it worked counts, except when a booking or verification result's body reads like an error (an `error` field, `ok: false`, a status of "failed"): then it reads Couldn't check, never Failed or Passed, since a guess must not decide either way. With no signal at all, it reads Couldn't check.
- **LiveKit end reasons are mapped to the reasons the engine already reads.** A participant disconnect means the caller hung up. A session the agent or code closed means the agent ended the call.

## Evidence and numbers

- **Every eval case so far is constructed, and labelled that way.** The cases are scrubbed calls from our own demo agent, named breakages of them, and reports generated by LiveKit's own library from our scripts. These cases show the engine does what we meant. They don't show how it does on other teams' calls, and no independent precision number is published until real calls are measured.
- **A locked eval case fails CI when its verdict changes.** A pinned call (`npm run check:pinned`) fails when any item its owner ticked changes.

## The product

- **Local first.** The Retell key and every call stay on the user's machine. The app listens on 127.0.0.1 only and refuses requests from anywhere else. The cost: about five minutes of setup, and no team sharing yet.
- **"Keep as a test" locks Overhear's verdict on a call.** It does not yet replay the call against the agent. Replay is the next step.

## The public demo

- **Real product, sample calls.** The hosted page runs the real engine on sample calls when it loads. Most samples are named edits of one real call, which is why their rows show no start time: they would all share one, and Overhear doesn't invent times.
- **A visitor's own call is private and short-lived.** It's shown only to that visitor, through a signed cookie, and kept in memory for an hour. Nothing is written to disk or a database. There is no live transcript, so the server's key never sits behind a public socket.
- **Spend is capped.**
  - Each visitor gets 3 calls per 10 minutes and 6 a day. The server takes 30 an hour, and each call is capped at 5 minutes.
  - A start Retell rejects gives its slot back.
  - The owner of a hosted copy logs in at `/owner` to skip the public limits during a demo.
- **Hosted copies fail closed.** Public pages open only with `OVERHEAR_PUBLIC_SAMPLES=1`, and a hosted copy with no password answers 503 instead of opening everything.
